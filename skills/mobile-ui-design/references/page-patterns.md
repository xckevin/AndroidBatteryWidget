# 页面模式

按产品任务选用。以下是可组合的结构，不是必须具备的页面清单。

| 场景 | 推荐阅读顺序 | 关键判断 |
| --- | --- | --- |
| 状态/工具首页 | 核心数据 → 含义与时间 → 主要操作 → 运行状态 → 常用入口 | 大数值要有上下文；实际状态与用户“已开启”设置分开 |
| 内容型首页 | 用户当前任务/内容 → 继续入口 → 相关内容 | 不把数据英雄卡机械套在阅读、社交或电商产品上 |
| 列表/设备管理 | 标题和必要动作 → 状态/筛选 → 条目 → 对应空状态 | 长列表保留虚拟化；主信息、辅助状态、行操作层级清楚 |
| 编辑/配置 | 预览（若有价值）→ 内容选择 → 行为 → 外观/高级项 → 保存与取消 | 编辑的是草稿还是立即生效必须明确；不同保存范围写清楚 |
| 表单/提醒 | 用户要配置的选项 → 就地校验 → 必要条件 → 保存 | 阻断使用的权限/账号条件应及时出现；非阻断说明不必占满首屏 |
| 设置 | 主题分组 → 简洁标题/说明 → 当前值/状态 → 相关入口 | 一个状态只在必要位置完整表达；不要层层卡片包住原生列表 |
| 付费解锁 | 可获得的价值 → 免费/付费边界 → 实际价格和状态 → 购买/恢复 | 仅已有或明确要求付费能力的产品使用；不自行决定收费边界 |

## 状态与动作

| 条件 | 呈现与动作 |
| --- | --- |
| 加载 | 保留稳定布局，说明正在获取；重复提交需受控 |
| 空数据 | 区分首次使用、无结果、没有设备；提供与原因对应的下一步 |
| 缺少权限 | 解释被影响的能力，提供真实可用的授权/设置入口 |
| 断连或过期 | 标出断连/更新时间；保留历史值时标明历史，不作为当前值强调 |
| 失败 | 保留用户输入和已有有效内容，提供重试或修正方法 |
| 保存 | 明确是保存当前对象、默认项还是全部设置；返回后能验证结果 |
| 不可购买/查询失败 | 显示真实不可用原因或状态，禁用不可执行购买；恢复入口依据能力保留 |
| 已解锁/处理中 | 分别展示已有权益和等待状态，不把 pending 当作成功 |

功能不可用时，选择“隐藏、禁用并解释、提供替代入口”要依据可发现性和用户目标，不能只为了画面整洁静默吞掉动作。

## 桌面小组件等受限界面

仅在项目包含 widget、扩展等受限界面时使用：应用内预览和宿主渲染可能走不同布局，分别验收。窄尺寸先保留最重要信息，宽尺寸再增加次要内容；缩放后点击目标和辅助说明不能失配。不要把应用内图片预览当作实际桌面添加/缩放已经通过的证据。
