# 验证与证据

## 按改动选最小有效组合

| 维度 | 建议检查 | 通过证据 |
| --- | --- | --- |
| 主题 | 涉及页面的浅色、深色 | 真实截图，无不可读文字、错色系统栏或禁用状态伪装 |
| 空间 | 目标最窄窗口、短横屏、较长本地化文本 | 主要动作、表单和关键内容可见或可滚动到达 |
| 字体 | 默认、较大及目标平台支持的辅助字号 | 允许重排，无重叠/截断；150% 可作初筛，不能代表最大字号已通过 |
| 键盘 | 聚焦低处输入框、显示/隐藏键盘、返回 | 输入、校验和保存可达，没有双重留白 |
| 状态 | 本次涉及的加载/空/权限/错误/不可用等 | 呈现对应实际条件，恢复操作有效 |
| 持久化 | 修改、取消、保存、返回，必要时重建/重启 | 草稿与已保存数据符合原有契约 |
| 无障碍 | 主要控件的触摸区域、读屏顺序、状态和对比度 | 名称/值/动作准确；装饰不干扰导航 |

不必执行整个笛卡尔积。选最容易出问题的组合，例如“窄屏＋英文＋大字体”和“短横屏＋编辑器”，再覆盖受影响页面的典型状态。

## 真实操作优于绕过布局

构建通过只证明能编译。检查滚动可达性时必须实际滚动、确认可见并发送触摸；直接调用 click handler、performClick 或只测业务函数，不能证明用户能按到保存。保留保存结果、返回目标或数据变化等业务断言。

旋转相关测试先等待目标配置、必要时的新 Activity/页面实例、视图布局和系统窗口稳定，再注入触摸。一次真实三星测试中，新 Activity 已恢复但旋转窗口仍在变化；有界窗口事件静默等待解决了注入触摸未到达的问题。它只是一个诊断方向，不是所有超时的原因：先查生命周期、当前页面、日志和实际保存结果；不要通过去掉真实点击或延长结果超时掩盖问题。

## 证据与维护

- 使用项目已有构建、静态检查和有意义的交互测试。不要为单纯颜色/间距改动新增镜像实现的断言。
- 截图后实际观察；视觉预览、模拟器、真机、桌面宿主、真实交易分别标明，不能互相替代。
- 最终验证应对应交付构建；若后续改了相关布局，补查受影响场景。保留已发现失败与修正结果，勿把“部分通过”写成整轮成功。
- 使用可用设备工具，设备标识在会话中发现，不写死个人序列号或账户。优先隔离模拟器/测试数据；恢复本次改变的临时全局设置并说明留下的测试对象。
- 没有真机、配件、登录或有效商品时，完成可执行的设计/代码/模拟器检查，准确记录缺失条件。不得为了验证视觉绕过正式构建的权益判断。
- 结束时沉淀主题位置、组件约定、覆盖范围和新发现的可复用教训。只有能改善下一次决策的经验才加入规范，不积累无限检查项。
